### 1.1《Attention Is All You Need》摘要

从「为什么需要 Attention」出发：

```text
FNN（前馈网络）→ RNN（循环网络）→ Encoder–Decoder（固定长度 C 的瓶颈）
        ↓
Attention（解码每个词时回看编码器全部位置）
        ↓
Self-Attention → Multi-Head Attention → Transformer 整体架构
```

**第一部分：动机铺垫（为什么要抛弃 RNN）**

- **FNN**：数据只向前走，核心是 `y = f(Wx + b)`，即「输入 × 权重 + 偏置 → 激活函数」；输入长度固定，无法建模词序。
- **RNN**：按 token 顺序逐个处理，用隐藏状态 `h`（可理解为「短期记忆」）携带上下文，支持不定长输入，因此长期是 NLP 的主力结构。
- **RNN 的两个致命问题**：
  
  1. **不能并行**：`h1 → h2 → h3 → h4` 必须串行依赖，前一个没算完后一个没法算，浪费 GPU 并行能力；
  2. **长距离依赖**：句子变长后，早期信息经过多步传递容易衰减（例："**我**…最后发现**我**忘记买相机了"）。
  - LSTM / GRU 通过「门」机制让模型学会选择性地记忆和遗忘，但没有解决串行瓶颈。
- **Encoder–Decoder**：Encoder「读懂」、Decoder「说出来」，中间用固定长度的上下文向量 `C` 传递信息。
  
  - **瓶颈**：整句信息全部塞进一个 `C`，句子越长丢得越多；
  - **且权重不对等**：不同词之间的关联强度本来就不同（例：比如**【我爱水课】**中**「课」**对**「水」**的权重应高于**「我」**对**「水」**）。
  - → 这就是 Attention 出现的原因：**Decoder 生成每个词时不再只看最后一个 `C`，而是回头查看 Encoder 的所有位置，动态决定当前该重点关注哪个词。**

### 1.2 Transformer架构分析

https://tu.842111.xyz/file/组会文件/组会汇报-2026-09-23/1790149140134_fig1-transformer-architecture.png

https://tu.842111.xyz/file/组会文件/组会汇报-2026-09-23/1790149136560_fig2-attention.png

**fig1自下而上读图，左侧 Encoder、右侧 Decoder：**

**关键模块逐个说清楚：**

1. **Embedding**：按 token ID 查一个可学习的向量。向量中的语义由训练形成，不是人工给每一维贴标签。Decoder 的 Output Embedding 做的是同一件事（处理目标语言已提供的 token），不是"把最终输出再转换一次"。说人话就是把词转换成向量，把人类语言 → 转换成计算机能处理的数字表示。

2. **Positional Encoding**：Transformer 和我们刚才讲的 RNN 不一样。RNN 天然是：

   ```
   我 → 爱 → 摄影
   1    2     3
   ```

   一个一个读取，所以天然知道顺序。

   但是 Transformer 可以同时看：

   ```
   我    爱    摄影
   ↓     ↓      ↓
   一起处理 
   ```
   为了让模型知道谁在前谁在后，所以加入：

   Positional Encoding（位置编码），相当于给每个词贴个号码

   ```
   我       爱       摄影
   ↓        ↓         ↓
   位置1    位置2     位置3
   ```

   所以图里的这个，可以理解成：**这个词是什么 + 这个词在哪里**

   ```
   Embedding + Positional Encoding
   ```

3. **Add & Norm**（残差连接 + 层归一化）：

   Add 让模型在原表示基础上增量更新，同时改善梯度传播；Norm 对每个位置向量内部特征做归一化，并配合可学习的缩放/平移，使训练更稳定（注意：它不会把所有 token 变成同一个向量）。

   > **Add：保留一份原来的信息，再加上新学到的信息。**
   > **Norm：把结果整理一下，让训练更稳定。**

   ```
   原来的信息 ─────────┐
                       ↓
   Attention结果 ───→ Add → Norm
                       ↓
                    新的信息
   ```

   其中这个绕过去的箭头，就是经常听到的**Residual Connection（残差连接）**。

4. **FFN**（逐位置前馈网络）：

   > Attention：**词与词之间交流。**
   > FFN：**每个词拿着交流后的结果自己加工。**

   例如：

   ```
   我 ────┐
   爱 ────┼→ Attention：大家互相交流
   摄影 ──┘
              ↓
          Feed Forward
              ↓
          进一步加工
   ```

   然后又经过一次：

   **Add & Norm**

   至此一层 Encoder 就结束了。至于图左边的*N，文中N为6 ，也就是Encoder堆叠了六层

5. **Decoder以及Outputs (shifted right)**：

   假设我们要把：

   > 「我爱摄影」

   翻译成：

   > **I love photography**

   Decoder 最大的特点：

   **不是一次把整句话蹦出来，而是一个词一个词生成。**

   例如：

   ```
   开始
    ↓
   I
    ↓
   I love
    ↓
   I love photography
    ↓
   结束
   ```
   训练的时候，假设正确答案是：

   > I love photography

   会把正确答案**右移一位**作为 Decoder 的输入。

   大概可以理解成：

   ```
   给 Decoder：<开始>
   让它预测：I
   
   给 Decoder：<开始> I
   让它预测：love
   
   给 Decoder：<开始> I love
   让它预测：photography
   ```

   所以 Decoder 一直在学习：

   > **根据前面已经有的词，预测下一个词。**

6. **Masked Multi-Head Attention（掩码多头注意力）**：训练时整段答案已在手上，但预测 `love` 的位置不能看到后面的 `love`、`photography`，否则等于偷看答案。因此每个位置只能看到「当前位置及之前」。由于输入已右移，当前位置提供的是预测目标之前的 token，因此「可看自己」与「不看答案」不矛盾。

   ```
   正在预测 love：
   
   I      love      photography
   ↑       ↑             ↑
   能看    当前          ❌ 不许看
   ```

7. **Query、Key、Value**：可以把 Q、K、V 想象成：

   ```
   Q（Query） = 我在找什么？
   K（Key）   = 我有什么特征？
   V（Value） = 我实际携带什么信息？
   ```

   假设现在模型正在理解：

   > **「喜欢」**

   它需要看看其他词对理解“喜欢”有没有帮助。

   可以把 Q、K、V 想象成：

   ```
   Q（Query） = 我在找什么？
   K（Key）   = 我有什么特征？
   V（Value） = 我实际携带什么信息？
   ```

   用一个非常生活化的例子：

   > 你去图书馆找一本“摄影入门书”。

   那么：

   ```
   Q = 你的需求
       “我要找摄影相关的书”
   
   K = 每本书的标签
       “摄影”
       “计算机”
       “美食”
       “历史”
   
   V = 每本书真正的内容
   ```

   于是：

   **Q 和 K 比较 → 找到最匹配的书 → 获取对应的 V。**

   Attention 基本就是这么回事。

   ok回到例子：

   每个词都会生成自己的 Q、K、V。

   ```
                 我        喜欢       摄影
                 │          │          │
                 ▼          ▼          ▼
               Q K V      Q K V      Q K V
   ```

   比如现在模型要理解：

   > **“喜欢”**

   那么“喜欢”的 **Q** 就会和所有词的 **K** 比较：

   ```
                  Q（喜欢）
                     │
             ┌───────┼───────┐
             ▼       ▼       ▼
           K(我)   K(喜欢)  K(摄影)
             │       │       │
           比较     比较      比较
   ```

   最后可能得到：这里只是举个例子，百分比并不是训练所得

   ```
   我        20%
   喜欢      30%
   摄影      50%
   ```

   意思就是：

   > 模型理解“喜欢”时，认为“摄影”提供的信息比较重要。

8.  **Multi-Head Attention**

   这是整篇论文最重要的东西：

   假设：

   > **我 喜欢 用 相机 拍 鸟，因为 它 很 漂亮。**

   当模型处理 **“它”** 的时候，它应该关注谁？

   可能重点关注：

   ```
   相机   拍   鸟   它   漂亮
    ↑          ↑    ↑
   较低        高   当前
   ```

   Attention 做的事情就是：

   > **让每个词看看其他词，并判断“哪些词和我最有关系”。**

   所以：

   ```
   我 ─────────┐
   喜欢 ───────┤
   摄影 ───────┤
   相机 ───────┼→ Attention → 得到结合上下文的新表示
   照片 ───────┘
   ```

   ------

   之所以叫Multi-Head，因为模型不是只从一个角度看。可以粗略想象成模型有好几双“眼睛”：

   ```
                「我 爱 摄影」
                     ↓
           ┌─────────┼─────────┐
           ↓         ↓         ↓
         Head 1    Head 2    Head 3
           ↓         ↓         ↓
        看语法      看语义      看关系
           └─────────┼─────────┘
                     ↓
                 合并结果
   ```
   
   这只是帮助理解的比喻，不代表每个 Head 一定固定负责某种语言功能。
   
   **三个要注意的点：**

   - 多头是**多组参数并行计算**，不是把句子切成几段分给不同头，也不是头与头之间依次传递结果；
   - 每个头都会完整执行一遍"打分 → 缩放 → 掩码 → Softmax → 乘 V"；
   - 不能断言"某个头必然负责语法、另一个必然负责语义"——分工是训练中自发形成的，未必可解释；
   - 这里Multi-Head Attention的 `Linear` 与 Decoder 最后那个词表 `Linear` **作用不同**：前者融合特征，后者为候选 token 打分。
   
9. **Linear -> Softmax**：

   经过 Decoder 后，模型内部得到一堆数字。

   但我们最终需要的是：

   > 下一个词到底是什么？

   于是经过：

   **Linear → Softmax**

   Softmax 可以理解成：

   > **给词表里的每个候选词计算概率。**

   例如：

   ```
   当前：
   
   I love ______
   
   
   模型预测：
   
   photography   80%
   camera         8%
   photos         5%
   football       1%
   apple          0.1%
   ...
   ```

   于是模型选择：

   > **photography**

   然后继续预测下一个词。

   最终：

   > **I love photography.**
   
### 1.3 总结

>   传统 RNN Encoder-Decoder 依靠隐藏状态按顺序传递信息，而 Transformer 使用 Self-Attention 让序列中任意位置直接交互，并通过并行计算提升了长文本建模能力，因此成为现代大语言模型（GPT、BERT等）的基础架构。

3. **写作体验**:写作时上传即得外链，直接在 Markdown 中引用，`![...](https://tu.842111.xyz/...)`；
4. **可扩展**：后续博客的相册、音乐播放器等模块的素材，都可以统一由这里承载。
