## 1.知识库归档：哪些保留，哪些简化

**我的想法：隐私文件材料仅自己和老师可以调取，同时减少重复填写和维护。**

| 事项 | 建议取舍 |
|---|---|
| 签字材料 | **重点保留**：签字后留清晰照片或PDF扫描件 |
| 系统已通过的材料 | 主要是**备份**为主，不强制截图、登记 |
| 目录与说明 | 主目录统一，每个主要环节一份 README，写清“留什么、放哪里”，但是尽量精简 |
| 命名与周报 | 文件名能辨认材料、日期即可；周报围绕“本周结果—遇到的问题—下周计划” |
| 共享范围 | 论文、代码和研究方法按需共享；个人隐私文件限制访问，避免全组可修改 |

**说明文件里需要明确区分：**

```text
学校要求提交什么 → 按学校通知办理
组内必须归档什么 → 明确列出
建议留存什么     → 直接标注“不强制”
特殊情况需要什么 → 有此情况再准备
```

科研材料优先保留支撑论文结论的代码、数据、参数和关键结果，以及开题、送审、答辩等节点版本，不要求把全部临时文件都存下来。

NAS方案建议双机热备 不选择上云

## 2.论文阅读

**这周私事比较多所有并没有实际的学习成果,暂时只是大致了解了一下这篇论文的内容,原本想尝试复现实验 发现他论文的基座是不公开的所有只能放弃,下周找一篇开源的论文尝试复现一下**

**<<ReAct: Synergizing Reasoning and Acting in Language Models>>**

| 项目       | 内容                                                         |
| ---------- | ------------------------------------------------------------ |
| 会议       | ICLR 2023（The Eleventh International Conference on Learning Representations） |
| 发表形式   | 会议论文（conference paper，非期刊）                         |
| 时间线     | v1 2022-10-06 投稿 → v2 2022-11-27 → **v3 2023-03-10（ICLR camera-ready）** |
| 机构       | 普林斯顿大学计算机系（Princeton CS）+ Google Research, Brain team |
| 基座模型   | PaLM-540B（主实验），GPT-3 text-davinci-002（附录对比）      |
| 任务覆盖   | 4 个基准：HotpotQA、FEVER（知识密集型推理）；ALFWorld、WebShop（交互式决策） |
| 一句话结论 | 让 LLM **交错生成"推理（Thought）"与"行动（Action）"**，兼顾性能、可解释性与可控性 |
| 项目主页   | https://react-lm.github.io/                                  |

**这篇论文提出了一个叫 ReAct（Reason + Act）的通用提示范式，用来让 LLM 把"推理"和"行动"交错起来解决任务。**

具体来说：以往工作把两条路线分开做——一条是 CoT（思维链），让 LLM 用**内部知识**一步步推理，但它是"静态黑箱"，不与外部世界接触，容易产生 **hallucination（幻觉）** 和错误传播；另一条是纯 Act，只让 LLM 输出动作去和外部环境（如 Wikipedia API）交互，但缺少高层目标推理，拿到信息也不会用、还会重复出错。

ReAct 的核心做法是**把动作空间从 A 扩展到 Â = A ∪ L**（L 为语言空间）：在普通动作之外，允许模型产出一个叫 **Thought** 的特殊动作。Thought **不改变环境、不产生 Obs（观察）**，只是把当前上下文 ct 中"有用信息"推理出来并写回上下文，从而支持**后续的 reason 或 act**。于是"Reason to act（推理以行动）"和"Act to reason（行动以推理）"形成双向协同。

## 3.数学建模参赛总结

此次比赛主要是意识到赛题也在与时俱进，题目中添加了对应的误导 AI 的内容，进一步考察了学生对数据、实验的敏感性，而且现时代的比赛其实更多是选手对提示词的把控力和模型能力的比赛
